# TS-02 — Full C-Package Staged Handoff

**Status:** exploratory candidate schema; equal phase status; unranked; not selected.  
**Lens:** closure/realization  
**Primary claim lane:** S-R  
**Candidate version:** v1

## One-sentence idea

A handoff succeeds structurally only when a heterogeneous staged bridge preserves or re-establishes one globally coherent C1–C8 package and passes a target-native withdrawal audit.

## Formal objects and types

- **Source object:** `CPkg(X_S)`
- **Target object:** `CPkg(X_T)`
- **Common comparison type / relation:** A typed package specification CPkg_* plus source/target realization maps and a global coherence object.
- **Transported-object atlas IDs:** TO-01;TO-12
- **Invariant IDs:** IV-04;IV-08
- **Bridge IDs:** BR-10;BR-06
- **Bridge signature:** B_stage = (exactify, transport, promote, glue, audit_T, withdraw) with typed contracts between stages.
- **Bridge morphology:** staged package morphism with exactification, promotion, event admissibility, global gluing, and autonomy gates
- **Bridge data:** clause witnesses C1–C8; cross-clause dependency graph; promotion tests; event package; resources; withdrawal record
- **Admissibility:** Every stage is independently typed; no clause witness is imported across carriers by renaming; one target carrier/package satisfies all coherence gates.

## Exact and approximate versions

- **Exact preservation:** declared hard clauses and gates; route-sensitive historical clauses may be re-established only with explicit lineage records
- **Permitted variation:** implementation details and gauge representations not entering the package contract
- **Approximate/noisy version:** A vector defect for each clause plus hard gate failures, with a stability theorem required before any approximate pass.

## Carrier, support, and clocks

- **Source status:** H-SOURCE-FULL must be stipulated or separately established; it is not inherited from the corpus.
- **Target status:** H-TARGET-FULL is a goal; separate component witnesses do not suffice.
- **Support through stages:** Mixed-support stages are allowed but each clause witness and event role must name its current support; final package is target-native.
- **Clock/order structure:** Clause-specific clocks are connected explicitly; temporal closure cannot be supplied by an unowned external scheduler.

## Preservation audit

- **Hiddenness/public matching:** C4/non-exposure is re-audited relative to target interfaces; a larger interface may alter the predicate.
- **Action credit/provenance:** C5 provenance is preserved or re-minted only under a declared endogenous rule; copied labels do not count.
- **Temporal closure:** C6 and package-minted order are part of the hard audit, including route and dormant-interval effects.
- **Recombination/global structure:** Global event and binding coherence include recombination-sensitive tests.
- **Viability/maintenance:** C8 and target-native maintenance are hard gates but remain lane-separated from lineage.

## Route, composition, branching, and deletion

- **Route policy:** Intermediate stages may be partial, but completion requires a globally coherent endpoint; route independence needs confluence on all retained package data.
- **Loop/holonomy test:** Run a closed handoff/reversal route and audit every clause, coherence edge, and historical residue.
- **Composition:** Compose only when target package outputs of one stage satisfy the source contract of the next and global glue is preserved.
- **Copy:** Multiple certified targets remain multiple structural successors; certification never selects one token.
- **Fission:** Branch-valued package continuation if every branch has its own coherent package and an admissible shared-prefix history.
- **Fusion:** Fusion-valued only after conflict resolution and one globally coherent fused package are proved.
- **Deletion:** Deletion is outside the certificate preservation proof and cannot restore uniqueness.
- **Empty target:** No target episode satisfies the integrated package and coherence gates.

## Controls and possible later theorem forms

- **Positive control:** S18 with the named package interpreted as the full audited contract.
- **Negative control:** S30 certificate-only migration with package mismatch.
- **Strong adversarial case:** S15/S31 local records that fail global gluing.
- **Possible theorem shapes:** Conditional package-preservation theorem; local-to-global package theorem under explicit glue; staged composition theorem; package-shadow separation theorem.
- **Possible no-go/boundary shapes:** Separate C1–C8 witnesses do not imply an integrated target; certificate equality does not imply package equality or lineage.
- **Toy discriminators:** finite eight-clause package with one incompatible glue cycle; certificate-only counterfeit; gradual route with one missing temporal/credit gate; target collapse after withdrawal.
- **Smallest reconnaissance model:** Eight finite clause predicates over two carrier types, one dependency cycle, one staged bridge, and one withdrawal transition.
- **Minimal dependencies:** finite predicates, dependency graphs, event records, exhaustive gate checks; no full simulation

## Falsification and kill criteria

- **Direct falsifier/downgrade test:** A model passes every declared stage/gate while lacking one required full-package clause or coherent global package.
- **Kill criteria:** No nonvacuous integrated finite package can be specified; certificate is irreducibly circular; stage composition requires the theorem being sought.
- **Nearest alternative:** TS-06 on discriminators S02;S17;S28;S35.
