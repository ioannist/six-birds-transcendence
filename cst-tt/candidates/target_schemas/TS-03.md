# TS-03 — Causal-Overlap Process Continuation

**Status:** exploratory candidate schema; equal phase status; unranked; not selected.  
**Lens:** dynamical/process  
**Primary claim lane:** S-L  
**Candidate version:** v1

## One-sentence idea

Structural continuation is an uninterrupted causally coupled process whose operational responsibility moves across distinct supports, not a matched endpoint reconstructed after the process stops.

## Formal objects and types

- **Source object:** `ProcHist(X_S)`
- **Target object:** `ProcHist(X_T)`
- **Common comparison type / relation:** A changing-support process history H over a joint time/order base with source and target support projections.
- **Transported-object atlas IDs:** TO-13;TO-08
- **Invariant IDs:** IV-11
- **Bridge IDs:** BR-07;BR-02
- **Bridge signature:** O = (H, supp(t), coupling(t), responsibility(t)) with nonzero causal/process overlap and target takeover.
- **Bridge morphology:** moving-boundary overlap process
- **Bridge data:** stage histories; causal dependencies; support shares; responsibility map; handoff completion and withdrawal events
- **Admissibility:** No stage gap in the selected process; overlap carries the named process invariant; source/target labels do not define continuity.

## Exact and approximate versions

- **Exact preservation:** selected process organization and causal update relation through every overlap stage
- **Permitted variation:** component identity, support allocation, representation, and local timing within the process connection
- **Approximate/noisy version:** A process-simulation tube with lower bounds on coupling/organizational continuity and explicit gap tolerance only if separately defined.

## Carrier, support, and clocks

- **Source status:** Finite process stipulated for exploration, not an actual conscious source.
- **Target status:** Target must continue the selected process and later operate without source/bridge support.
- **Support through stages:** The process may straddle X_S and X_T during overlap; final responsibility lies on X_T.
- **Clock/order structure:** A shared partial order across coupled events is required; identical rates are not.

## Preservation audit

- **Hiddenness/public matching:** Operational causal organization may be privileged and is not inferred from public smoothness.
- **Action credit/provenance:** Only preserved if causal provenance flows through the overlap; copied credit labels do not suffice.
- **Temporal closure:** Uninterrupted event order is central; dormant gaps are excluded in the strict version.
- **Recombination/global structure:** Fork and merge points are explicit process events, with no automatic global glue.
- **Viability/maintenance:** The strict handoff additionally requires target operation after source withdrawal, but process lineage and autonomy stay separate lanes.

## Route, composition, branching, and deletion

- **Route policy:** Replacement order can matter; process continuity is route-specific unless all critical pairs commute on the selected organization.
- **Loop/holonomy test:** Compare two replacement schedules and their intermediate causal organizations, not only final states.
- **Composition:** Concatenate overlap histories only when the terminal mixed process of one leg is the initial process of the next.
- **Copy:** A detached copy is a new target process; if a continuous process genuinely forks, the lineage relation branches from the fork.
- **Fission:** Branch-valued only for a causally continuous fork, not for independent reconstruction from a record.
- **Fusion:** Requires an actual coupled process merger; endpoint state fusion alone is insufficient.
- **Deletion:** Deleting the source after a detached copy does not retroactively create process continuity.
- **Empty target:** No target process lies on an uninterrupted admissible moving-support history.

## Controls and possible later theorem forms

- **Positive control:** S01 or S22 with explicitly preserved process organization and final takeover.
- **Negative control:** S02 destructive scan with no live overlap.
- **Strong adversarial case:** S13 long-lived coupling in which the target is only a source-driven shadow.
- **Possible theorem shapes:** Overlap-preservation theorem; detached-copy separation theorem; composition of moving-support histories; critical-pair obstruction.
- **Possible no-go/boundary shapes:** Endpoint equality plus source deletion cannot establish process continuation; temporal gaps fail the strict uninterrupted criterion.
- **Toy discriminators:** finite causal network with one moving support boundary; detached clone versus live handoff; forked process; two noncommuting replacement orders.
- **Smallest reconnaissance model:** A 4-node causal process whose update responsibility migrates across two disjoint node sets, plus a detached clone control.
- **Minimal dependencies:** finite directed event graphs, support labels, causal reachability, route enumeration

## Falsification and kill criteria

- **Direct falsifier/downgrade test:** An accepted bridge contains a stage with no selected process instance or admits a detached reconstruction indistinguishable from overlap by its own data.
- **Kill criteria:** Process invariant cannot be specified without presupposing identity; overlap requirement trivializes all nonoverlap protocols; no composition law handles mixed stages.
- **Nearest alternative:** TS-08 on discriminators S02;S06;S18;S21.
