# TS-05 — Encoded Logical-Package Migration

**Status:** exploratory candidate schema; equal phase status; unranked; not selected.  
**Lens:** error-correcting/logical-object  
**Primary claim lane:** S-T  
**Candidate version:** v1

## One-sentence idea

A higher-layer package persists across changing supports when encoding, recovery, and decoding preserve one declared logical object with bounded defect, while target-native recovery is tested separately.

## Formal objects and types

- **Source object:** `CodePkg(X_S)=(C_S,Enc_S,Dec_S,Rec_S,L_S)`
- **Target object:** `CodePkg(X_T)`
- **Common comparison type / relation:** A logical package space L_* with source and target encoders/decoders.
- **Transported-object atlas IDs:** TO-14;TO-15
- **Invariant IDs:** IV-09;IV-10;IV-06
- **Bridge IDs:** BR-09;BR-05
- **Bridge signature:** Dec_T o Rec_path o Channel_ST o Enc_S ~= id_L on an admitted logical domain.
- **Bridge morphology:** encode–recover migration channel, optionally through changing code spaces
- **Bridge data:** logical package; code spaces; error model; syndrome/defect signals; recovery maps; code-change intertwiners
- **Admissibility:** Code and error model are declared before testing; recovery does not import the desired output; target-native recovery is separately located.

## Exact and approximate versions

- **Exact preservation:** logical package modulo declared gauge/code equivalence
- **Permitted variation:** physical support, redundant encoding, syndromes, and correctable errors
- **Approximate/noisy version:** Logical defect bounded below threshold for a declared horizon, with code-change and recovery composition laws.

## Carrier, support, and clocks

- **Source status:** A finite encoded package stipulated in toys.
- **Target status:** Target may initially carry a bridge-supported logical state; autonomy requires internalized recovery.
- **Support through stages:** The logical object may be distributed over changing source/target support; code membership is explicit at every stage.
- **Clock/order structure:** Recovery-cycle order is explicit; target-local operation after handoff is separate.

## Preservation audit

- **Hiddenness/public matching:** Syndromes reveal code-relative defects but not all package-relevant hidden structure.
- **Action credit/provenance:** Preserved only if included in the logical code; QEC analogy alone does not add it.
- **Temporal closure:** Preserved only if encoded as part of the logical package and generated target-natively.
- **Recombination/global structure:** Code switching and branch merge require logical intertwiners; branchwise fidelity is insufficient.
- **Viability/maintenance:** Recovery resources and thresholds are part of the autonomy audit.

## Route, composition, branching, and deletion

- **Route policy:** Different code-switch routes may have logical holonomy; route independence requires commuting intertwiners modulo gauge.
- **Loop/holonomy test:** Encode, migrate, decode, optionally return, then compare logical state and hidden logical residue.
- **Composition:** Compose channels with a proved logical-error budget and compatible code interfaces.
- **Copy:** Classical logical packages may be duplicated, yielding branch-valued structural successors; no-cloning-like restrictions must be stated if relevant.
- **Fission:** Branch-valued if the encoding law intentionally creates multiple qualifying logical packages.
- **Fusion:** Fusion-valued only through a declared merge code that resolves incompatible logical records.
- **Deletion:** Source erasure is neither required nor sufficient for logical preservation.
- **Empty target:** No decodable target logical package remains within the admitted code/error domain.

## Controls and possible later theorem forms

- **Positive control:** S25 adaptive error-corrected migration.
- **Negative control:** S13 external decoder/source process.
- **Strong adversarial case:** S12 logical predictive match with unencoded action-credit/binding mismatch.
- **Possible theorem shapes:** Logical-package preservation under recoverable support changes; code-switch composition; threshold stability; external-decoder autonomy separation.
- **Possible no-go/boundary shapes:** QEC analogy supplies no consciousness code automatically; code-relative fidelity cannot settle token identity.
- **Toy discriminators:** finite repetition-like package code; moving support with one correctable defect; external versus internal recovery; route-dependent code switch.
- **Smallest reconnaissance model:** A 3-bit logical package encoded over two support sets with one recovery channel and one external-decoder counterfeit.
- **Minimal dependencies:** finite codes/channels, relation matrices, exhaustive error enumeration, route composition

## Falsification and kill criteria

- **Direct falsifier/downgrade test:** The declared logical package changes under an error designated correctable, or target success depends on an undeclared external decoder after withdrawal.
- **Kill criteria:** No principled package-to-code map; recovery merely reconstructs outputs from source; thresholds cannot cover package hard gates.
- **Nearest alternative:** TS-09 on discriminators S02;S13;S19;S24.
