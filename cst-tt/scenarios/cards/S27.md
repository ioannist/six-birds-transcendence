# S27 — Partial replacement around a persistent shared core

**Battery item:** 27 (supplemental stress control)
**Plan wording:** Most support is replaced, but one causally central core remains continuously active across the whole process.
**Cross-carrier/control status:** `partial_carrier_change_persistent_core_control`
**Outcome vector:** deliberately unfilled (`S-T=UNFILLED; S-R=UNFILLED; S-L=UNFILLED; A=UNFILLED; R=UNFILLED`)
**Machine records:** `scenarios/PROTOCOL_AXIS_MATRIX.csv` and `ledgers/scenario_discriminator_matrix.csv`, keyed by `S27`

## 1. Discriminating purpose

Test whether criteria depend on amount of replaced material, a privileged persistent component, or package-level causal organization.

## 2. Stipulated scenario facts

- A declared core support token remains active throughout while all peripheral support is replaced.
- The core alone is not stipulated to realize the full package.
- Target-side peripherals progressively assume all noncore roles.
- A counterfactual variant replaces the core last, permitting a direct comparison.

These facts define the case. They do not preassign transport, target-package, lineage, autonomy, recognition, or ontological outputs.

- tiny versus large core
- core stores memory versus only clocking

## 10. Blocked inferences

- Persistent matter is not identity by definition.
- A central component is not necessarily the package carrier.
- Partial overlap does not settle cross-carrier typing.
- Replacing everything except one token is not automatically same-carrier persistence.

## 11. Nonclaims

This card does not say whether a conscious subject moves, survives, dies, branches, fuses, or is recreated. It does not assert that the source or target is conscious. It defines an operational stress case for later structural candidates.
