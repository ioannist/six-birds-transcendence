# S25 — Adaptive error-corrected migration

**Battery item:** 25 (supplemental stress control)
**Plan wording:** A logical package is maintained across changing noisy supports by repeated syndrome-like recovery.
**Cross-carrier/control status:** `genuine_cross_carrier_qec_analogue`
**Outcome vector:** deliberately unfilled (`S-T=UNFILLED; S-R=UNFILLED; S-L=UNFILLED; A=UNFILLED; R=UNFILLED`)
**Machine records:** `scenarios/PROTOCOL_AXIS_MATRIX.csv` and `ledgers/scenario_discriminator_matrix.csv`, keyed by `S25`

## 1. Discriminating purpose

Use the strongest engineering analogy as a stress case while keeping code space, recovery law, package realization, and consciousness interpretation separate.

## 2. Stipulated scenario facts

- A declared logical package is encoded across source-side physical degrees of freedom.
- Support membership changes gradually while recovery acts using measured defect signals.
- Logical fidelity is residual-bounded under a declared error model and horizon.
- At the endpoint the original support and migration controller can be removed, but target-native recovery must be separately tested.

These facts define the case. They do not preassign transport, target-package, lineage, autonomy, recognition, or ontological outputs.
