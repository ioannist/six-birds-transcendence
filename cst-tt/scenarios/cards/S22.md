# S22 — Live migration under concurrent source updates

**Battery item:** 22 (supplemental stress control)
**Plan wording:** State is copied while the source continues changing, then a cutover reconciles in-flight updates.
**Cross-carrier/control status:** `genuine_cross_carrier_concurrent_update_case`
**Outcome vector:** deliberately unfilled (`S-T=UNFILLED; S-R=UNFILLED; S-L=UNFILLED; A=UNFILLED; R=UNFILLED`)
**Machine records:** `scenarios/PROTOCOL_AXIS_MATRIX.csv` and `ledgers/scenario_discriminator_matrix.csv`, keyed by `S22`

## 1. Discriminating purpose

Expose consistency, cutover, and causal-order obligations hidden by static before/after copies.

## 2. Stipulated scenario facts

- The target receives an initial state while the source continues processing events.
- A finite update log or reconciliation protocol transfers in-flight changes before cutover.
- During migration, public outputs may be routed through either side according to a schedule.
- After cutover the source is erased, and the reconciliation bridge is removable.

These facts define the case. They do not preassign transport, target-package, lineage, autonomy, recognition, or ontological outputs.

## 10. Blocked inferences

- A zero-downtime cutover is not lineage by definition.
- Eventual public consistency is not global event-package identity.
- A log is not necessarily complete history.
- Reconciliation policy is not neutral if it discards branch information.

## 11. Nonclaims

This card does not say whether a conscious subject moves, survives, dies, branches, fuses, or is recreated. It does not assert that the source or target is conscious. It defines an operational stress case for later structural candidates.
