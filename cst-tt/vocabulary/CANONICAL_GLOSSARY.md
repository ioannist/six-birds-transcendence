# Canonical Glossary

**Status:** provisional and target-neutral. These definitions regulate the exploration; they do not settle the science.

Every entry contains a “not to be confused with” field. Formal candidate work should use the term ID when ambiguity is likely.

## Hosting

### G001 — substrate

**Provisional definition.** A declared underlying state-transition-resource organization capable of supporting one or more implementations. It may be physical, computational, biological, hybrid, or abstract, but its level of description must be stated.

**Use rule.** Use only with a declared description level and dynamics.

**Not to be confused with.** the mathematical carrier used to model it; a material label; consciousness.

### G002 — medium

**Provisional definition.** A family or class of substrates treated as sharing a declared implementation grammar or operational affordance.

**Use rule.** Use comparatively, with the shared grammar named.

**Not to be confused with.** a single carrier token; an ontologically fundamental stuff.

### G003 — carrier

**Provisional definition.** The typed state-bearing object on which a model’s dynamics, interfaces, resources, and package structures are defined. In the finite SBT setting this is often a finite state set plus declared structure.

**Use rule.** Always index source/target carriers separately.

**Not to be confused with.** substrate in full physical detail; support; package.

### G004 — carrier specification

**Provisional definition.** The full record `(id, X, H, D, U, interfaces, resources, admissibility)` used to type a carrier in this project.

**Use rule.** Preferred formal unit for cross-carrier comparison.

**Not to be confused with.** a bare state set.

### G005 — carrier token

**Provisional definition.** One numerically distinct instance of a carrier specification or implementation.

**Use rule.** Use when token multiplicity matters.

**Not to be confused with.** carrier type; structural equivalence; personal identity.

### G006 — carrier type

**Provisional definition.** An abstract class of carrier specifications sharing a declared signature.

**Use rule.** Use for polymorphic statements.

**Not to be confused with.** a theorem that all carrier tokens support equivalent realizations; A2.

### G007 — support

**Provisional definition.** The components, states, channels, or region actually bearing a package at a time or along a route.

**Use rule.** Declare whether support is fixed, changing, overlapping, or distributed.

**Not to be confused with.** the entire carrier; logical object; source-target lineage.

### G008 — implementation

**Provisional definition.** A declared relation or map by which an abstract package specification is instantiated in carrier dynamics and interfaces.

**Use rule.** State domain, codomain, and preserved operations.

**Not to be confused with.** phenomenal realization; public emulation.

### G009 — implementation map

**Provisional definition.** A typed map/relation from abstract package components to carrier-level states, histories, operations, or invariants.

**Use rule.** Use when comparing multiple realizations.

**Not to be confused with.** identity map across carriers; proof of implementation correctness.

### G010 — structural realization

**Provisional definition.** Satisfaction by a carrier-indexed target of declared package clauses and coherence gates.

**Use rule.** Project tag `S-R`; preferably say “structural instantiation.”

**Not to be confused with.** phenomenal realization; source-target lineage; certificate soundness.

### G011 — distinct carrier

**Provisional definition.** A source/target pair that remains separately typed after renaming and cannot be reduced to one fixed-support construction without losing declared bridge/support/dynamics facts.

**Use rule.** Must pass the carrier-distinctness audit.

**Not to be confused with.** different labels; different coordinates; a refinement on one frozen support.

### G012 — fixed support

**Provisional definition.** A construction in which the underlying support is held constant while descriptions, packages, protocols, or promoted layers change.

**Use rule.** Carry a visible fixed-support flag.

**Not to be confused with.** cross-carrier migration.

## Package

### G013 — package

**Provisional definition.** A typed tuple of structures, dynamics, interfaces, resources, clauses, and audits treated as one candidate higher-layer object.

**Use rule.** List components and carrier explicitly.

**Not to be confused with.** a single state; consciousness; certificate alone.

### G014 — source package

**Provisional definition.** The package instance declared on the source carrier at the relevant start history or interval.

**Use rule.** Write `P_S : Package(Σ_S)`.

**Not to be confused with.** the source person; every source microstate.

### G015 — target package

**Provisional definition.** The candidate package instance declared on the target carrier at the relevant endpoint or interval.

**Use rule.** Write `P_T : Package(Σ_T)`.

**Not to be confused with.** a guaranteed continuation; a public output copy.

### G016 — C-package

**Provisional definition.** The design-level eight-clause consciousness-relevant closure package C1–C8 plus declared coherence/audit conditions from the attached consciousness work.

**Use rule.** Treat as a structural target and specify full vs simplified form.

**Not to be confused with.** a proved sufficient condition for consciousness; an exhibited integrated instance.

### G017 — clause

**Provisional definition.** One declared requirement within a package, with its own carrier, evidence, temporal scope, and failure condition.

**Use rule.** Index and type each clause.

**Not to be confused with.** the whole package; empirical fact.

### G018 — closure

**Provisional definition.** A declared completeness or fixed-point property relative to specified operations, continuations, interfaces, or audits.

**Use rule.** Name the operator and fixed-point notion.

**Not to be confused with.** causal closure in every sense; phenomenal unity.

### G019 — closure-generated object

**Provisional definition.** An object defined as a fixed point, quotient, completion, or promoted survivor of a declared closure process.

**Use rule.** Candidate transported-object class only.

**Not to be confused with.** an object independent of carrier or route by definition.

### G020 — viability

**Provisional definition.** Controlled or endogenous persistence within a declared safe/feasible region under specified dynamics, actions, and resources.

**Use rule.** State kernel, horizon, and funding conditions.

**Not to be confused with.** biological life; consciousness; personal survival.

### G021 — viability kernel

**Provisional definition.** The greatest declared controlled-invariant safe set, or its project-specific analogue.

**Use rule.** Use carrier- and policy-indexed notation.

**Not to be confused with.** a subject; a lineage relation.

### G022 — promoted package

**Provisional definition.** A package accepted at a higher description layer after declared sufficiency, closure, stability, honesty, and strictness gates.

**Use rule.** State whether intrinsic or protocol-supported.

**Not to be confused with.** a package moved to a new carrier.

### G023 — public shadow

**Provisional definition.** The image of a package under a declared public/readout interface, possibly preserving outputs while discarding hidden or predictive organization.

**Use rule.** Use as a control object.

**Not to be confused with.** the full package; a counterfeit by ontological stipulation.

### G024 — counterfeit control

**Provisional definition.** A deliberately constructed target that matches selected public criteria while failing a named hidden, predictive, coherence, viability, or autonomy condition.

**Use rule.** Use to test criterion specificity.

**Not to be confused with.** a claim that the target is phenomenally nonconscious.

## Audit

### G025 — certificate

**Provisional definition.** A finite or otherwise auditable record of clause/gate satisfaction under declared interfaces and assumptions.

**Use rule.** Distinguish full C-package certificate and simplified schema.

**Not to be confused with.** certificate soundness; consciousness; identity.

### G026 — certificate soundness

**Provisional definition.** A theorem or assumption that certificate satisfaction is sufficient for the intended structural or ontological conclusion.

**Use rule.** State conclusion and scope exactly.

**Not to be confused with.** certificate satisfaction; audit completion.

### G027 — audit

**Provisional definition.** A declared check of a construction, map, defect, control, dependency, or gate whose scope and result are recorded.

**Use rule.** Audits can be analytic, computational, or mechanized.

**Not to be confused with.** proof beyond the checked scope; empirical validation.

### G028 — gate

**Provisional definition.** A named audit condition required before a claim or package receives a declared status.

**Use rule.** List pass/fail/NA and evidence.

**Not to be confused with.** the phenomenon being gated.

### G029 — admissibility

**Provisional definition.** A predicate defining which states, histories, actions, bridges, routes, observations, or interventions are allowed in a claim.

**Use rule.** Declare before evaluating preservation.

**Not to be confused with.** physical possibility in general; viability; certificate satisfaction.

### G030 — protocol honesty

**Provisional definition.** The condition that a claimed package or effect is not manufactured solely by an undeclared representation, scheduling, decoder, or comparison protocol.

**Use rule.** Test by protocol controls and removal interventions.

**Not to be confused with.** autonomy; correctness of every protocol.

## Connection

### G031 — bridge

**Provisional definition.** Typed data relating source and target carriers, states, histories, packages, or processes, together with admissibility and compatibility obligations.

**Use rule.** Always name bridge form and direction.

**Not to be confused with.** transport success; lineage; common support.

### G032 — route

**Provisional definition.** An ordered sequence or coupled process of bridge stages connecting declared source and target conditions.

**Use rule.** Path/order may matter.

**Not to be confused with.** a single bridge; a route-independent connection.

### G033 — handoff

**Provisional definition.** A declared interval/event in which responsibility for maintaining specified package functions shifts from source-side to target-side support.

**Use rule.** Define start, completion, and success criterion.

**Not to be confused with.** source destruction; lineage; an instantaneous state map.

### G034 — overlap

**Provisional definition.** A nonempty interval or region in which source and target supports jointly contribute to the declared package or bridge.

**Use rule.** Represent contributions explicitly.

**Not to be confused with.** graduality by itself; identity.

### G035 — translation

**Provisional definition.** A representation change preserving named structures or observables between typed domains.

**Use rule.** State what is translated and lost.

**Not to be confused with.** implementation; realization; lineage.

### G036 — transport

**Provisional definition.** A satisfied typed preservation relation for a named object/invariant under a declared bridge or route.

**Use rule.** Use only after specifying object, bridge, and defect.

**Not to be confused with.** movement of a subject; target realization; lineage.

### G037 — migration

**Provisional definition.** Informal protocol term for changing the support/carrier of an implementation over time.

**Use rule.** Translate into bridge, route, handoff, transport, and autonomy predicates.

**Not to be confused with.** a formal conclusion.

### G038 — transcendence

**Provisional definition.** Project-level informal umbrella for continuation beyond one substrate/medium.

**Use rule.** Forbidden as a primitive; decompose into tagged predicates.

**Not to be confused with.** a theorem, mechanism, or ontological fact.

### G039 — continuation

**Provisional definition.** A verdict assigned by an explicit lineage criterion to a source-target history pair.

**Use rule.** Never define by “the same continuing subject.”

**Not to be confused with.** transport, endpoint similarity, source destruction.

### G040 — route independence

**Provisional definition.** Equality/equivalence of outcomes for all admissible routes with common endpoints under a declared comparison relation.

**Use rule.** Requires a theorem, often flatness/confluence-like conditions.

**Not to be confused with.** existence of one successful route.

### G041 — route dependence

**Provisional definition.** A difference in declared outcome/invariant/lineage across admissible routes with common endpoints.

**Use rule.** Name the differing observable or predictive structure.

**Not to be confused with.** mere protocol inconvenience.

### G042 — holonomy

**Provisional definition.** The nontrivial action accumulated around a closed route/loop despite endpoint-level current agreement.

**Use rule.** Specify quotient and loop action.

**Not to be confused with.** any path dependence; entropy production; trauma.

### G043 — composition

**Provisional definition.** A typed operation combining bridges, transports, or lineage relations with stated domain/codomain and defect law.

**Use rule.** Associativity and closure are obligations.

**Not to be confused with.** automatic global coherence.

## Interface

### G044 — state

**Provisional definition.** A point in a declared carrier at one model time or stage.

**Use rule.** Use carrier index.

**Not to be confused with.** history; package; subject.

### G045 — history

**Provisional definition.** An admissible ordered record of states/actions/events on a carrier or coupled route.

**Use rule.** State duration and admissible continuations.

**Not to be confused with.** memory variable alone; identity.

### G046 — process

**Provisional definition.** A dynamics-bearing evolution or coupling, not merely a sequence of endpoint states.

**Use rule.** Use when causal generation or overlap matters.

**Not to be confused with.** history representation; state map.

### G047 — public interface

**Provisional definition.** The declared family of current observations, reports, readouts, or controls available at a specified boundary.

**Use rule.** Interface-relative by construction.

**Not to be confused with.** all behavior; all empirically accessible information; full state.

### G048 — predictive interface

**Provisional definition.** The declared admissible continuations and future observation family used to distinguish histories/states predictively.

**Use rule.** May be richer than the public interface.

**Not to be confused with.** omniscient future access; current report interface.

### G049 — observation lens

**Provisional definition.** A map from carrier states/histories to a declared observable value space.

**Use rule.** Name lens and fibers.

**Not to be confused with.** the thing observed; a complete description.

### G050 — current/public quotient

**Provisional definition.** Equivalence classes induced by agreement on declared current/public observations.

**Use rule.** Write `Q`.

**Not to be confused with.** predictive quotient; identity class.

### G051 — predictive quotient

**Provisional definition.** Equivalence classes induced by agreement under all declared admissible future continuations and observations.

**Use rule.** Write `M` and list continuations.

**Not to be confused with.** phenomenal state; cross-carrier lineage by itself.

### G052 — hidden state

**Provisional definition.** A variable or distinction not determined by a declared interface, possibly still measurable through another interface.

**Use rule.** Always interface-relative.

**Not to be confused with.** intrinsically unknowable state; phenomenal privacy.

### G053 — exposure

**Provisional definition.** Factorization of a determining variable through a declared interface, making it recoverable at that interface.

**Use rule.** State interface and determining variable.

**Not to be confused with.** visibility to every observer; loss of consciousness.

### G054 — predictive matching

**Provisional definition.** Agreement of declared future behavior under all admitted continuations.

**Use rule.** Scope to continuation family and horizon.

**Not to be confused with.** full package preservation; lineage; causal history.

### G055 — public matching

**Provisional definition.** Agreement at a declared public interface over a declared intervention/horizon set.

**Use rule.** Use as one observable relation only.

**Not to be confused with.** predictive matching; structural realization.

## Lineage

### G056 — identity

**Provisional definition.** An overloaded term that is invalid unqualified in this project. It must be replaced by token identity, structural equivalence, predictive equivalence, or a declared lineage relation.

**Use rule.** Always attach relation and scope.

**Not to be confused with.** similarity; continuity; consciousness.

### G057 — token identity

**Provisional definition.** Numerical identity of one declared object token through a formal identity rule.

**Use rule.** Requires a cross-time/cross-carrier token criterion.

**Not to be confused with.** isomorphism; qualitative identity; lineage.

### G058 — structural equivalence

**Provisional definition.** Equivalence or isomorphism with respect to a named structure family.

**Use rule.** List preserved structures.

**Not to be confused with.** token identity; shared history; consciousness.

### G059 — lineage

**Provisional definition.** A directed, history-sensitive relation connecting package instances under a declared criterion; it may be one-to-one, one-to-many, many-to-one, partial, or route-dependent.

**Use rule.** Use `S-L`; allow empty/multiple outcomes.

**Not to be confused with.** equivalence relation; endpoint matching; genetic lineage by analogy.

### G060 — successor

**Provisional definition.** A target package related forward to a source by a declared lineage criterion.

**Use rule.** May be nonunique.

**Not to be confused with.** the unique continuation; child copy; conscious subject.

### G061 — duplicate

**Provisional definition.** One of two or more numerically distinct target instances that are equivalent under specified source-relative criteria.

**Use rule.** State symmetry and differences.

**Not to be confused with.** a nonreal target; a unique successor.

### G062 — copy

**Provisional definition.** Informal term for a target constructed to match named source information.

**Use rule.** Replace with exact copied object and relation.

**Not to be confused with.** lineage, identity, realization.

### G063 — branch

**Provisional definition.** One member of a one-to-many lineage outcome under a declared criterion.

**Use rule.** State branch relation and shared ancestry.

**Not to be confused with.** unique identity continuation; mere computational fork.

### G064 — fission

**Provisional definition.** A route/outcome in which one source has multiple target successors under a declared lineage relation.

**Use rule.** Classify symmetry and uniqueness.

**Not to be confused with.** proof that all branches are one token.

### G065 — fusion

**Provisional definition.** A route/outcome in which one target has multiple source predecessors under a declared lineage relation.

**Use rule.** State what ancestral structures combine or conflict.

**Not to be confused with.** identity with every source token.

### G066 — extinction

**Provisional definition.** The absence of an admissible target successor under a declared lineage criterion.

**Use rule.** Criterion-relative and route-relative.

**Not to be confused with.** metaphysical annihilation; empty viability kernel alone.

### G067 — dissolution

**Provisional definition.** Loss of the structural conditions supporting a package or lineage relation on a carrier.

**Use rule.** State which predicates fail.

**Not to be confused with.** ontological death without an O premise.

### G068 — dormant interval

**Provisional definition.** An interval with no active target-package realization while some recovery-relevant record or potential remains.

**Use rule.** Specify what persists and recovery conditions.

**Not to be confused with.** continuity; extinction; sleep by analogy.

### G069 — reconstruction

**Provisional definition.** Creation of a target package from retained records after disruption or absence.

**Use rule.** Classify as repair, recreation, or underdetermined under `κ`.

**Not to be confused with.** automatic continuation; resurrection.

## Protocol

### G070 — destructive protocol

**Provisional definition.** A protocol in which the source package/support is deliberately disabled, overwritten, or made unavailable by a declared stage.

**Use rule.** State timing and what is destroyed.

**Not to be confused with.** proof of target lineage.

### G071 — nondestructive protocol

**Provisional definition.** A protocol in which the source remains available after target construction/handoff.

**Use rule.** Include duplication consequences.

**Not to be confused with.** absence of branching; source-target identity.

### G072 — gradual protocol

**Provisional definition.** A route with staged support replacement or contribution change over a nontrivial interval.

**Use rule.** Specify overlap and order.

**Not to be confused with.** continuity by definition.

### G073 — abrupt protocol

**Provisional definition.** A route modeled without an overlap interval or with a single declared transition stage.

**Use rule.** State temporal resolution.

**Not to be confused with.** destructive protocol; discontinuity.

### G074 — reversible protocol

**Provisional definition.** A route admitting a declared inverse up to a named equivalence and admissibility domain.

**Use rule.** State inverse and defect.

**Not to be confused with.** token identity; zero entropy; route independence.

### G075 — distributed realization

**Provisional definition.** A package structurally instantiated across multiple supports/components/carriers whose joint organization is required.

**Use rule.** Declare joint boundary and recombination/coherence.

**Not to be confused with.** multiple subjects; one subject; redundancy.

### G076 — autonomous target

**Provisional definition.** A target that maintains specified package predicates under target-endogenous dynamics after a declared removal intervention for a horizon or closure condition.

**Use rule.** Use tag `A` and name intervention.

**Not to be confused with.** isolation from environment; lineage; consciousness.

### G077 — bridge-dependent target

**Provisional definition.** A target whose relevant package predicates fail when the bridge, source, decoder, or protocol support is removed.

**Use rule.** Record dependency as an outcome.

**Not to be confused with.** a useless or unreal target.

### G078 — decoder-dependent target

**Provisional definition.** A target whose claimed structure exists only after applying a continuing external decoding/reconstruction map.

**Use rule.** Distinguish readout from carrier-side realization.

**Not to be confused with.** recovery-assisted autonomy after decoder internalization.

## Quality

### G079 — exact preservation

**Provisional definition.** Zero defect for a named structure under a declared equality/commuting/isomorphism criterion.

**Use rule.** State all preserved components.

**Not to be confused with.** total microstate identity; exact lineage.

### G080 — approximate preservation

**Provisional definition.** A named defect remains within a declared threshold over a stated domain and horizon.

**Use rule.** Declare metric, threshold, and composition law.

**Not to be confused with.** exact preservation; harmlessness; identity.

### G081 — defect

**Provisional definition.** A typed measure or witness of failure of a specific factorization, commutation, closure, invariance, or matching condition.

**Use rule.** Name zero condition and units/order.

**Not to be confused with.** global error; phenomenological loss.

### G082 — residual

**Provisional definition.** The mismatch remaining after an allowed fit, projection, repair, or optimization.

**Use rule.** State optimization family and baseline.

**Not to be confused with.** defect in every sense; unexplained essence.

### G083 — repair

**Provisional definition.** An operation that reduces a named defect, restores admissibility, or returns a package to a declared region.

**Use rule.** State whether continuity through repair is separately tracked.

**Not to be confused with.** proof that nothing was destroyed or recreated.

### G084 — robustness

**Provisional definition.** Persistence of a stated property under a declared perturbation family and bound.

**Use rule.** Declare perturbations and quantifiers.

**Not to be confused with.** autonomy; generality; empirical reliability.

### G085 — fidelity

**Provisional definition.** A scalar or relation measuring agreement with a named source object under a declared metric/test family.

**Use rule.** Use only as one quality measure.

**Not to be confused with.** lineage probability; consciousness amount.
