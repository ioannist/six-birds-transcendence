# MF-02 — Gradual mixed-support handoff

**Status:** exact finite reconnaissance model; specified but not implemented.
**Governing-plan slot:** gradual handoff model
**Phase:** CST-EXP-05

## Purpose

Give SF-02 a noncircular positive control and give SF-01 a staged target-ownership test.

## Exact finite signature

- **Carriers:** Source modules S0,S1 and target modules T0,T1 are four separately named support tokens.
- **States:** Process state q∈{0,1}; at each stage a support set A_k and two contribution bits c_k^a,c_k^b determine q_(k+1)=q_k xor c_k^a xor c_k^b.
- **Inputs/interventions:** One endogenous update input step plus an allowed disturbance bit d∈{0,1}; all values are finite and explicit.
- **Transition law:** Stage 0 uses {S0,S1}; stage 1 uses {S1,T0}; stage 2 uses {T0,T1}; stage 3 uses {T0,T1} after source withdrawal.  At stage 1 both S1 and T0 are nonredundant: fixing either contribution changes q_(2).
- **Interfaces/probes:** The operational event DAG records support ownership, causal parents, process signature q, local clock k, and a responsibility frontier.  No edge is labeled lineage in advance.
- **Bridge/episode data:** A corridor is the sequence A_0…A_3 plus signature-preserving update maps, one mixed nonredundant stage, no empty process stage, and target takeover at stage 2.

## Positive witness

The finite corridor connects source-only support to target-only support, preserves q, contains a genuine mixed update, and remains defined after source/controller withdrawal.

## Exact negative or counterfeit control

Use identical endpoint states but replace stage 1 by source termination followed by target initialization from a static record; the mixed-step predicate and overlap corridor fail.

## Required witness package

Stage table; causal DAG; nonredundancy certificates for both sides; no-gap trace; target-only invariant cycle.

## Controls

Pure source update; pure target update; bridge-controller-dependent target; same endpoint without mixed stage.
