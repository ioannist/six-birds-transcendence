## Raw construction, exact partial semantics and control declaration

Both actual execution paths begin with the same computed source-checked prefix. Native receipts are generated by executing actual steps and recording their actual before/command/after intermediates. Fusion recording binds that execution and its primitive program/token inputs; its projected World equals actualRun on every partial input. The combined ledger is actual native receipt edges plus the actual successful fusion command edges, all realized in the retained final graph. Runtime closure frames and stored Boolean tables are derived, not caller fields. Single-predecessor source-preserving rules add only ledger descendants of an already related predecessor.

Ancestry is exactly a genuine prefix predictive Seed followed by zero or more accepted native/fusion ledger edges. Zero additional edges follows an already positive-length Seed. Structural paths alone cannot create ancestry. None denotes unavailable execution, some false a present negative, some true the exact derived provenance. Occupied twins retain no incoming edge even when used as a later parent, so they remain ancestry-false; their outgoing fusion child can inherit the other ancestral parent. Empty fusion streams return their initial world and do not certify an arbitrary initial token ledger. run_resources explicitly requires its initial invariant; each successful nonempty step checks the global invariant itself.
