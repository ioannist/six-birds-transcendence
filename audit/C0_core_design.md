# C0 — kernel-checked finite Temporal-FIACH core design

Design only. No Lean or frozen science file is changed by C0. This is a proposed contract for manager/Eddy review, not a claim that the declarations below already compile. The trust base remains Lean 4.28 core (`propext`, `Quot.sound`, `Classical.choice`); no Mathlib, new axiom, placeholder, or global toolchain change is planned. C0E correction: [computed-semantics audit](C0E_evidence.md) supersedes any optimistic witness claim below; [FIACH-POS-02 draft](proposed_models/FIACH-POS-02.draft.json) is partial evidence, not a completed positive model. The eight-row registry order is TTN-03 → TTH-03 → TTN-04 → TTH-01 → TTH-02 → TTH-05 → TTH-04 → TTH-06. A positive handoff and an arrow-free countermodel cannot be the *same* interpretation of the endogenous-arrow predicate; see the explicit feasibility gate below.

**Data insufficiencies and alignment risks.** `TR-POS-01` is a useful separate nontrivial representative-independence control, but it is **not** a FIACH-POS-01 component: its source record edge is `3→4` and target edge `30→40`, whereas the FIACH package C6 edges are `0→1` and `3→4`. No certificate states the cross-model identification. The FIACH corridor's `transport_evidence` only names components and stores booleans; it does not supply representative classes or component maps. Thus nontrivial representative independence and future-sufficiency of *all* source/target histories cannot be claimed from FIACH-POS-01 alone. **In particular**, target C6 stores `future_sufficient = true`, yet its one static predictive tag and route list do not distinguish the four AUT-POS-01 states: the `nominal` transition from `T-SAFE-0` reaches phase 1, while from `T-SAFE-1` it reaches phase 0. If that C6 tag/list is the entire current code, these two states are current-equal with different future phases, so `FutureSufficientEncoding` is false. Taking the whole state as the code would make sufficiency trivial and would not implement the declared C6 code. The frozen model contains no state-dependent predictive quotient that resolves this. FIACH-POS-02 proposes a **new restricted** phase/progress/record interface, chosen with the frozen outcomes known. Its factorization is near-automatic because all eight transitions have identical progress and record deltas and flip phase; `SAFE-0` and `WARNING-0` share phase 0 but under `hit` reach warning and safe health respectively. This does not validate frozen static C6 future sufficiency. Other C6 booleans (`order_stable`, `successor_total_on_viable`, `tick_viable`, `arrow_endogenous`) must likewise be tied to finite transitions/ranks rather than accepted as conclusions. `COR-POS-01` has one leg, so it cannot itself exercise a two-leg composition. `AUT-POS-01` supplies one static target package contract and per-state `package_valid` flags, but no per-state package assignment; package preservation must be defined at its model-relative static-contract ceiling, with state/resource conditions explicitly checked. These are review gates, not values to fabricate.

**Required TTN-03 exception.** The positive package records `arrow_endogenous = true` and strict record advances; TTN-03 requires `¬ endogenous arrow`. Reusing the same model with the same arrow predicate would prove a contradiction. Its actual evidence is the separate [CM-03 model](../cst-tt/models/countermodels/CM-03.model.json), whose two three-state permutations do not commute and whose record update is constant. A truthful eight-row closure therefore needs **one positive handoff model plus this separate negative route control**. If “one model” is literal for every row, TTN-03 cannot be made faithful in this packet: remove it from the positive-model requirement and demote its status until a separate kernel check is authorized. Merely tagging CM-03 as a component of FIACH-POS-01 would hide the incompatibility. Its registry dependency `TTN-03 → TTN-04` is bookkeeping; TTN-04's logical proof does not require the positive handoff to lack an arrow.

## 3. Constructing TTH-06, field by field

The construction follows `TemporalFIACHCertificate` (`lean/CSTTT/Targets/TemporalFIACH.lean:17–44`) but removes its free `Prop` interfaces inside the model-linked wrapper. `source := ⟨17⟩`, `target := ⟨101⟩`, and `distinct` is `by decide`. `sourcePackagePremise` is definitionally `SourcePackageCheck fPos`; it needs source-package C6/C7 checks and operational C8 at assembly. It has no TTH-05 or per-state preservation premise. `stagedClausePreservation` is `StageMapCheck fPos`, proved from all scoped entries of STG-POS-02, without trusting `translation_attested`. `packageCertificate` would be the `TargetPackageWitness fPos` from TTH-02, with independently checked target C6/C7 and operational C8 at assembly; this witness is currently unavailable. TTH-05 then separately asks whether that package persists over controller states and disturbances. `corridorCertificate` is the single-leg `StrictCorridorWitness` from COR-POS-01, with source 17/target 101 and stage-0/stage-2 temporal-frontier links to source/target C6 assignments. `autonomyCertificate` would be `ExactAutonomyCertificate (autonomyData fPos)` from AUT-POS-01, with carrier 101, endpoint `T-SAFE-0`, and its handoff event equal to `t-exit`; only its operational invariant is presently evidenced. Package/corridor/autonomy endpoint equations are proved by reduction of those raw model fields, not by separate assumptions. The corridor exit tick 2 links to AUT endpoint `T-SAFE-0` phase 0 by `2 mod 2 = 0`, while carrier 101 and event `t-exit` agree exactly. **New-model dependency:** `FIACH-POS-02` supplies only an exploratory state-dependent phase code and two candidate event-dependency paths; it supplies no C7 histories, state-indexed package assignments, theory-route identification, or endpoint-persistent route provenance. Hence the following is a conditional construction recipe, not a presently executable constructor.

Set `routeStatus := routeStatusOf fPos.corridor` **only after** identifying which dependency paths count as theory routes and deriving their same-boundary comparison domain. `.flat` requires a nonempty comparison domain, covered critical pairs, unique normal form, and explicit path-clock translations with zero holonomy. `.routeIndexed` requires at least two theory routes with path-distinguishing provenance **retained at the common endpoint** and no certified flatness; it does **not** assert nonflatness. Otherwise use `.unresolved`. The frozen graph has two candidate paths through the mixed events, but both feed `t-exit`, which stores one residue list. Neither the theory-route identification nor endpoint persistence is supplied. Thus frozen `route-indexed` is a **declared model status with computed path multiplicity**, not a substantive memory pass; computed `routeStatusOf` is unresolved on current evidence. Growing stage residue alone proves no nonflatness. No flatness certificate is available. Set `recognitionStatus := .notAddressed`, matching the certificate and the structural claim ceiling. A recognition verdict is not inferred from a structural handoff. The wrapper should not expose constructors accepting arbitrary source/stage propositions or arbitrary route-status labels as a route to the registered theorem. The old generic `TemporalFIACHCertificate` may remain as a schema interface, but it alone is not evidence for TTH-06.

The final concrete theorem should have no success-flag premise: `theorem fPos_fiach : Nonempty (ModelLinkedTemporalFIACHCertificate fPos)`. **C0E blocks this theorem on current evidence:** FIACH-POS-02 only supplies a near-automatic restricted temporal code and candidate dependency paths, while endpoint route provenance, C7 integrated binding, TTH-05 per-state package preservation, and TTH-03 representative histories are unavailable. The operational C8 kernel itself is a substantive pass. It must not be implemented by projecting old flags. If new evidence arrives, its proof sequence is source package → stage map → target package → corridor → autonomy → endpoint/owner/route links → certificate constructor. The generic TTH-06 theorem then reads out the three independently verified lanes. This is a finite, model-relative structural precursor; it neither proves recognition nor unbounded physical survival.
