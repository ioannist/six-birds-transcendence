## Raw, observer and resource freezes

The physical state is `(outside,u,v,replica,phase)`, all Bool. Kernel order is
`00,01,10,11`; each kernel outcome has both replica outcomes. Inside maintenance
weights per replica are `[1,3,3,1]`, `[3,1,1,3]`, `[3,1,1,3]`, `[2,2,2,2]`.
Outside maintenance weights are `[2,2,2,2]`. Scale is **16**. Maintenance returns
inside and flips phase; probe has one weight-16 outside outcome preserving
kernel/replica and flipping phase. The public lens remains 0 inside and
`1+2*(2*bit(u)+bit(v))+bit(phase)` outside. Flat control weights remain 2.
No primitive is a partition, stationary law, directional verdict or clause.

The default address-capability inventory is **0 through 7**, with one storage
capability per address. Stronger family: any finite prefix 0 through N−1,
N≥4, with the same operations; no extra token or energy is thereby created.
Address0 initially houses the source. A birth consumes its capability once;
retired addresses cannot be reborn. Allocation outside the supplied inventory
rejects. This is bounded hardware per world, not free fresh storage forever.
Node IDs are typed event/version/birth IDs with generated ordinals; they are
not timeless carrier addresses or token serials. Native histories are unbounded.
The unit storage capability licenses one resident slot; it is not a finite-bit
bound. Locally owned append memory/counters and archived protocol storage are
explicit unbounded mathematical resources, retained with the declared model.
No finite-memory or physical storage-cost theorem is claimed.

Token IDs are exactly **0,1,2,3**. Initially token0 belongs to local source0,
token3 to the external bridge service; tokens1/2 are unallocated. Every token
initially stores **1** energy unit and has port cursor0. Allocation distinguishes
unallocated, recorded reservation, live local/external custody, and retired
custody. IDs cannot be duplicated. Each live resident holds a nonempty set of
exclusively owned tokens; its primary key is the least token in that set.
An enabled native step debits **1**, consumes exactly its primary port's next
`Option Unit` packet, credits **1** iff present, and increments that cursor.
Native actions cannot silently switch to a spare key. Missing supply preserves
the initially charged step and then disables that key; it does not conjure
energy. No operation mints a token or copies a charge balance.

Each birth records its actual primary cursor and custody epoch. Native serials
stay `4*cursor+token`; local record count comes from that residency's generated
list, not a serial decoded as though every token started at cursor0. A fused
owner can inherit a nonzero cursor on a differently numbered token. Temporal
transport must use the consumed actual counts and birth offsets, never assume
owner=token or reset an inherited cursor.

Renewable packets are retained environmental resources; packet suppliers never
become receipt issuers. Administrative reserve/snapshot/activation/partition
costs are explicitly **0** energy in this structural model; birth additionally
consumes one supplied storage capability. Fusion debits one primary unit from
each parent, with separately consumed packets. This is an open-system unit
energy model, not a physical manufacturing or persistence theorem.

The fixed CURRENT family remains public lens plus the two native row-mass
channels, restricted to maintained inside support. No credit bit, predictor,
fusion-availability channel or full receipt payload is added to CURRENT.
Branch emissions are kernel bits on actual successors, zero outside, **after
actions**. Full native eight-role laws include the **initial observation**:
predictive class, local order, phase, progress, native record count, immutable
birth residue, primary maintenance charge, owner. Order/progress/count measure
actual paid local native steps. Birth residue now records actual typed source
or parent-version roots and their consumed relative contexts; it is immutable.
Complete receipts remain available for audit, not a ninth observation role.

Compute native refinement and full native future laws from the frozen rows.
The required contextual code is physical class × actual eight-role context;
matching contexts are not an extra premise. The extended **protocol** command
language has separate world/optional-resident laws and a full raw-world readout;
the old native quotient is not asserted to classify all new protocol futures.
Keep C1/C2/C3/C4/C7/C8's accepted G27 design meanings and observer domains.
Only the new receipt-boundary C5/C6 implementation is redesigned explicitly.

## Installed fission, fusion and one least ancestry

Snapshot writers read a live installed source, its owned enabled key and latest
actual supported receipt. They capture program, state, source version, serial
and actual order/count. Consumers require an unused reservation and fresh birth
capability, install exactly that captured program/state, consume the slot, and
start a new owned residency with **zero** local receipts. No supplied decoder,
issuer or source package verdict is accepted. Captures have no wall-time expiry;
wrong epoch, spent capability, stale reservation or altered payload rejects.
Bootstrap's common capture writes two distinct recipient-bound one-time slots;
each is consumed once. Sharing the source version does not reuse a spent slot.
Source-only retirement, a deterministic zero-energy administrative operation,
can remove the source while retaining already deposited recipient slots. Their
consumers validate the historical capture epoch, not current source presence;
later full withdrawal clears all unconsumed slots. Require a destructive-gap
acquisition control as well as the default overlapping bootstrap script.

The disconnected-twin control uses a separate, explicitly frozen independent
boot command in this same raw operator language. It requires an acquisition-stage
hardware capability, an unoccupied never-born address, and one genuinely
unallocated charged key; reserved or live keys reject. A request selects only
one of the two registered ROM program IDs. Hardware installs that actual ROM
at the frozen all-false initial physical state, binds the key to the new owner,
consumes the birth capability, and generates its custody/birth receipt with an
empty native history. Energy cost is **0**, supported probability **1**; guard
failure changes nothing. Its hardware-origin edge has no source edge, and its
local credit still requires actual warmup. Withdrawal removes independent-boot
authority. This control cannot reuse keys already reserved for the main script.

Freeze both fission mechanisms. Bootstrap fission reserves the actual charged
unallocated keys1/2 for two fresh children, using one source capture for both;
the source retains token0 until withdrawal. Resource-partition fission divides
a composite parent's token set into two nonempty disjoint sets covering it,
retires that parent, and transfers those keys to two fresh children. Both copy
the parent's current program/state, produce actual custody/birth receipts, and
start new local logs. Neither inherits a local self-credit verdict or creates
energy. Insufficient keys or fresh capabilities rejects. This supports further
forks with pooled keys rather than silently restricting fusion to singleton
token parents. Both mechanisms are deterministic, probability **1**, when their
guards pass; certification may require the declared local warmup afterward.

Fusion requests name two distinct live parent versions, their native Bool
actions and a fresh output capability. **No merger program, coupling table,
normalizer, credits list or issuer is a request input.** Hard guards require:
installed equal program identities; authenticated resident/address bindings;
disjoint nonempty parent token sets; every transferred local allocation housed
by its actual parent; charged primaries; unused output capability; unoccupied
output; exclusive IDs/reservations; and positive, normalized scale-16 native
input rows. These guards do not require a package verdict or a chosen cycle.

Let actual input edges be `(zL,nL)` and `(zR,nR)`. Form the list of **all edge
pairs with zL=zR**, retaining edge identities and replica/phase. Its integer
total W is the sum of `nL*nR` over that list. For W>0 the new atomic protocol
row assigns probability **nL*nR/W** to each such pair. This is the independently
defined product kernel conditioned on exact physical meeting, including phase
and replica. W is computed, never supplied; there is no adjustable epsilon,
coupling or outcome acceptance score. It is a conditional sampler, not a claim
that the resulting parent marginals equal their unconditioned native laws.
There are no hidden rejected sampling trials or uncharged retries.

For each supported pair the installed protocol performs both paid, authorized
input advances, recording their actors from their pre-transfer custody, their
actual row weights, packets, serials and before/after contexts. The atomic
receipt records the conditional probability as well as both native support
weights. Then it retires both parent residents, transfers **every** parent
token/remaining charge/port cursor into the fresh output owner's custody,
consumes the output capability, and installs the common program at z. Output
native history starts empty, primary is the least transferred key, and both
parent versions/context roots are retained. Parent receipts cannot count as
output-owned native cycle evidence. Retirement leaves archived provenance, not
active ghost parents. No interleaving occurs inside this atomic protocol.

Hard-guard failure is unavailable/rejected, with no state change, allocation,
debit or lineage edge. When the administrative guards and input normalization
pass but W=0, return a distinct **empty settlement**, probability **1**, with
the entire execution world unchanged and a returned computed diagnostic receipt.
There is no output birth or accepted ancestry edge. The receipt references the
prospective output birth/address; it does not consume that capability or mint
a graph vertex. Empty-target truth is tied to this actual settlement, not to
any arbitrary absent or occupied address. Source ancestry to both live parents
remains available. Missing inputs never default to this empty arm.
The ambient node type includes a separate prospective-reference tag, indexed
by parent versions, actions and the unused output capability. It has no accepted
edges. A later actual birth at that address has a distinct generated birth ID;
an old empty receipt cannot classify that resident as an empty target.

The accepted event ledger generates one strict path relation on typed nodes:
initial source birth → successive paid native versions; captured source version
→ snapshot event → each activated child birth; parent version → child births
for partition fission; both actual input parent versions → their paid input
versions → fusion event → output birth. Each native continuation also supplies
its before-version → generated event → after-version edges. Events only refer
to already generated parents, so creation order is acyclic. Independent boot
has its own hardware origin and no source-root edge. Rejected and empty
settlements contribute no accepted edges.

Define ancestry as the **least edge-containing transitive relation**, with
no-ex-nihilo proved from the ledger, not supplied as raw data. Historical source
ancestry is its restriction from the actual source birth; parent-to-fused
ancestry uses actual parent versions in the same relation. This instantiates
the original TTF-04 formula without treating targets as historical-source seeds.
The old source-only seed/target-descendant refutations remain true in Legacy.
No numerical-identity equivalence or invariant singleton selector is inferred.

## Receipt boundary and whole-package autonomy

The proposed C5/C6 boundary is a **current residency epoch**, not “the entire
receipt list must end exactly at a cycle boundary.” Reconstruct and validate
the entire epoch's native execution from its actual installed birth, local
custody receipt and generated native records: supported transitions, consecutive
states, actual issuer/lease/program, serial/cursor updates and packet/debit
accounting. Absent packets are recorded truthfully; enabled current maintenance
is a separate gate. Normal history cannot be erased or restarted by a native
action; changing owner/program or birthing a new resident starts a fresh epoch.

Directional evidence ranges over **every contiguous nonempty closed block**
of that epoch's actual ordinary maintenance receipts. Compute full-state forward
and reverse products from the current immutable installed program. Require
nonzero unequal products, present consumed packets in the block, and homogeneous
local-owned issuance. Continuing whole-epoch authenticity and current owned
funding remain required. Evidence is recomputed from records; no “credited”
primitive or initialized sticky Boolean is allowed. A previously computed
qualifying block survives a legal append, without declaring an open tail closed.
Protocol receipts, copied source blocks, pre-transfer parents and another epoch
cannot supply the local witness. Flat, symmetric/internalized, mixed, wrong-owner,
missing-program or tampered histories must exercise their actual readouts.
Required process bridge: the block's inequality must certify irreversibility
of the **current** immutable installed generator, with positive owned access
from every maintained current state to the relevant loop. Mere persistence of
an old badge, without this current-process/ownership bridge, fails promotion.
Scheduled/internalized controls must exercise this new block rule or its proved
generic specialization; their legacy readouts remain unchanged.

This choice comes from C5's generator/process irreducibility, C6's endogenous
continuing records, and TTF-05's **package-containing invariant**. A completed
experiment can certify a fixed generator while its authenticated operation
continues; a closed audit-tail alignment is not the same process property.
It addresses G29 by retaining authentic evidence, not by hiding odd prefixes,
removing phase, selecting favorable response outcomes, adding macro-steps,
storing a supplied verdict, or weakening autonomy to resource-only continuation.
Whether this is the intended original C5/C6 reading is an owner decision below.

Source/bridge/snapshot access, migration driver, external decoder/scheduler and
