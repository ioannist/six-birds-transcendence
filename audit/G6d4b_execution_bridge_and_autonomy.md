## Executed bridge and frozen signatures

`ExecutionBridge.Raw` permits separately typed source and target register
programs on **one immutable assignment**. Its translation is raw instruction
syntax. Source/target initializers, history words, rows, successors, code,
observations, closure, snapshots and exact finite alphabets are interpreted,
not candidate arguments. This internal engine uses a common disturbance,
action and outcome interface; the encompassing typed component extraction
remains required.

`ExecutionBridge.Laws` checks:

- identical audit selection and outcome enumeration;
- equality of the interpreted history words;
- initializer translation;
- equality of every branch probability at every source-closure state;
- successor commutation for all declared disturbances/actions/outcomes on that
  whole closure;
- all eight observation fields after translation on that whole closure.

`fold_commutes` derives supported execution commutation by induction.
`snapshot_map_check` then derives the map equations; it does not accept them as
an independent display. `frozen_transport` constructs and transports every
field of the frozen `TemporalSignature`. Each full-future sufficiency proof is
obtained separately by the existing class-mass induction, with its one-step
alignment checked on the interpreted dynamics. Its quantifiers remain all runs
and all finite words, not a bounded horizon or snapshot-only probe.

`representative_independence` derives equality of target predictive images from
source predictive equality on the audited frontier. No independence verdict is
stored in raw data.

## Generic game-to-TTH-05 projection

The frozen TTH-05 `Carrier` is finite; the game run space need not be.
`GameAutonomyTransport` therefore supplies an **internal interpretation engine**
with explicit, proved projection laws. It makes no decision-completeness or
omitted-context assertion.

`game_each_entry_exact` extracts the strategy's reachable-play invariant using
`game_invariant_completeness`. The finite `inside` region is then **defined** as
its projection image. The endpoint is the projection of the actual entry.
Neither is a supplied finite safety region. `projectedCertificate` constructs
all the existing `ExactAutonomyCertificate` fields from the game and projection
laws. `projected_response_all_support` retains every actual positive-support
branch of a chosen normalized, target-owned response before deriving TTH-05's
existential response. `game_each_entry_finite_words` applies the existing
`postWithdrawalFiniteHorizonInvariance` for every genuine entry and every finite
disturbance word.

`POS04GameAutonomyTransport.projection_laws` proves these obligations for
arbitrary partial assignments satisfying the existing computed full game/AF
gate, using the actual updater and actual row supports. There is no assumption
that budgets, tape, counters or route registers can be omitted. The fallback in
`project` is unreachable on the package/legal contexts used in the proof:
those contexts prove an actual `inK` factor.

Only the static withdrawal/boundary/resource ownership facts are reused from
the existing computed TTH-05 adapter. Its old response and old inside region
are **not** used to construct the new invariant image or response proof.
`full_game_each_entry_exact`, `register_game_each_entry_exact` and
`full_game_each_entry_words` export the new construction. `positive` and
`positive_entries_and_support` establish genuine nonempty entries and
all-support preservation. `lineage_control_each_entry` shows the registered
lineage-only failure still admits the same post-exit transport.
